# 个人知识工作台 — 规划文档

> 规划日期：2026-09-12（未来两天内敲定选型并跑通最小闭环）
> 定位：本地优先服务 + 开源 + 可同步到 GitHub 跨设备使用
> 关联现有项目：[[stock_analysis_agent_plan.md]]（炒股早报Agent）、[[personal_ledger.md]]（个人档案+财务台账）
> 本文档基于 5 路并行调研（PKM基座/理财工具/知识图谱构建/内容抓取/Git同步隐私方案）综合而成，结论截至 2026-09。

---

## 一、项目愿景

搭建一个"个人知识工作台"，覆盖四类需求：

1. **日常个人理财**：记账 + 持仓看板
2. **读书笔记**：日常看书笔记留存
3. **炒股学习资料整理**：把投资大师的书拆解成读书笔记，按**人物**分别建立知识图谱（核心观点/方法论/案例/与其他人物的关联）
4. **行业观察拓展**（AI产品经理工作相关）：收集其他公司 CEO/高管/产品负责人的公开言论、职业经历、产品思考、行业判断，逐步扩展知识库

两条腿走路：**本地端**提供服务、离线可用；**GitHub 端**公开/半公开，方便跨设备同步。

**核心判断（来自调研）**：不建议从零造一整套 PKM 系统——现成开源笔记工具在"纯文本+双向链接+图谱视图"上已经很成熟，重新做投入产出比很低。真正需要自己写代码/接脚本的地方，是"LLM抽取书籍→人物笔记"和"私有/公开数据的同步与隔离"这两块粘合逻辑。

## 三、四大模块选型建议

### 1. 笔记基座（承载读书笔记 + 知识图谱 + 行业观察）

| 候选 | 开源协议 | 数据格式 | 图谱能力 | 结论 |
|---|---|---|---|---|
| **Obsidian** | 核心闭源（免费），插件多为MIT | 100% 纯 Markdown | 双向链接+图谱视图，插件生态最强（Dataview可把笔记当数据库查） | 综合性价比最高，但不满足"工具本身开源"这条 |
| **Logseq** | **AGPL-3.0 完全开源** | 纯 Markdown/Org | 大纲式双向链接+图谱视图，可挂 property 做轻量结构化字段 | 满足开源要求，插件生态和大库性能弱于 Obsidian |
| SiYuan思源笔记 | AGPL-3.0 开源 | .sy（JSON块），非纯文本 | 图谱能力强，中文本地化最好，自建Web服务开箱即用 | 落地格式不是纯文本，git diff/纯文本编辑体验打折扣 |

**建议**：因为你明确要求"工具开源"，默认推荐 **Logseq**（AGPL全开源、纯Markdown、天然适合git管理）。如果后续发现插件生态/性能是硬瓶颈，再切 Obsidian（数据都是Markdown，迁移成本低，不构成锁死）。→ 这是需要你拍板的第一个决策点，见第八章。

### 2. 理财记账与持仓看板

| 候选 | 开源协议 | 部署复杂度 | 特点 |
|---|---|---|---|
| **beancount + Fava** | GPL-2.0 / MIT | 极轻（`pip install`即可，无需数据库/容器） | 纯文本账本，原生支持按成本法记录基金/股票持仓，Python库可被自己脚本/Agent直接读写，天然对接 stock_agent |
| Firefly III + Ghostfolio | 均 AGPL-3.0 | 中（各自Docker+数据库） | 开箱即用好看看板；Ghostfolio 有持仓分析+实验性MCP（可被AI Agent直接当工具调用），但要求Postgres+Redis |
| Maybe Finance | AGPL-3.0（**官方已弃维护**） | — | 不建议新起步选用 |

**建议**：先上 **beancount + Fava**——部署成本几乎为零，且和你现有 stock_agent（Python+AKShare）技术栈一致，容易打通。如果以后觉得看板不够好看，再叠加 Ghostfolio 做持仓可视化（两者可以共存，beancount 账本导出数据喂给 Ghostfolio）。

### 3. 知识图谱构建方法（书籍 → 人物知识图谱）

调研了 GraphRAG / LightRAG / LlamaIndex PropertyGraphIndex / Neo4j / RDF 等"正规"图谱方案，结论是：**对个人、非团队场景，这些都过度设计**——门槛高、产物是数据库文件不可读不可改，和笔记系统是两套割裂系统。

**建议方案（起步用最轻的）**：
- 用 **Logseq/Obsidian 的 Markdown + `[[双向链接]]` 直接模拟知识图谱**：零基础设施、人和LLM都能直接读写、可长期迁移
- 每本书 → 用 LLM（Claude）按固定模板一次性抽取 → 写成对应人物的笔记：
  ```
  # 人物：沃伦·巴菲特
  ## 核心观点
  ## 方法论
  ## 经典案例
  ## 关联人物
  - [[本杰明·格雷厄姆]]（安全边际概念来源）
  - [[查理·芒格]]（长期合作伙伴，多元思维模型）
  ```
- **可逆升级路径**：以后如果需要"多跳查询"（比如"找出所有和格雷厄姆安全边际观点有关联的人物"），可以把这些 Markdown 内容喂给 **LlamaIndex PropertyGraphIndex**（默认零基础设施，可自定义抽取schema）叠加一层正式图查询——从数据库退化回笔记很痛苦，反过来升级很轻松，所以从最轻的方案起步。

### 4. 行业人物言论采集（CEO/高管内容抓取）

| 候选 | 开源协议 | 特点 |
|---|---|---|
| **Karakeep**（原Hoarder） | AGPL-3.0 | Docker自托管，**自带LLM自动摘要/打标签**，整页归档(monolith)对社交媒体页面兼容性最好，yt-dlp可顺手存播客/访谈视频，天然适合"抓取→LLM提炼→写回笔记"闭环 |
| Readeck | AGPL-3.0 | Go单文件+SQLite，运维成本几乎为零（老树莓派都能跑），但无内置AI能力，一切自动化要自己接API |
| Wallabag | MIT | 协议最宽松、最老牌稳定，但没有AI能力，社媒页面抓取效果一般 |
| Omnivore | AGPL-3.0 | **官方云端已关停**，纯社区维护，不建议拿来起新项目 |

**建议**：如果本机方便跑 Docker，上 **Karakeep**（抓取+LLM初步提炼一步到位）；如果暂时不想装Docker，先用 **Readeck**（几乎零运维）或者干脆手动摘录存进笔记，等模块成熟再上工具。

## 四、隐私与同步架构（关键：财务数据不能裸奔到公开仓库）

调研明确排除了"单仓库+加密"方案：`git-crypt`/`git-secret` 官方都自认没有"撤销授权"能力，密钥一旦泄露或加密规则漏配一次，**历史 commit 永久且不可逆地暴露**，拿来护财务数据风险收益不成比例。

**推荐架构：双仓库物理隔离**

| | 公开仓库 | 私有仓库 |
|---|---|---|
| 内容 | 读书笔记、炒股知识图谱、行业观察人物卡 | 财务账本(.beancount)、持仓、账户具体数字 |
| GitHub | 公开 repo | 免费私有 repo（个人账号私有仓库数量不限，纯存文本笔记用不到Pro功能） |
| 同步工具 | Obsidian Git 插件（或同款思路脚本）：定时自动 commit→pull→push | 同上，走另一个 remote |
| 引用规则 | 只能写"加仓了某只股票"这类文字描述 | 具体金额/账户号只留在私有库，**不要**用具体数字反向链接进公开内容 |

注意事项：
- Obsidian Git 插件移动端基于 isomorphic-git，官方标注"highly unstable"，**财务数据同步不要依赖手机端**，以桌面端为主
- 冲突处理走原生 git 机制，没有智能合并，出现冲突要手动清理 `<<<<<<<` 标记
